# v0.1 "Browser" Implementation Plan

**Status:** executed — steps 0–14 completed, release 0.1.0 (2026-10-19;
gate and results: `docs/reports/v0.1-measurements.md`, sections 4 and 10). The
plan version after review (2026-10-18): incorporates all review comments
and the contract decisions with Kartograf (decisions 2–5 and 8 below).
**Scope:** strictly local, read-only access to the Kartograf store; Archiwista's
writes are configuration, the rebuildable index and the permissions state database
(accounts, groups, project visibility; step 8b) on the local disk.
The following apply in order: `PRD.md` and `SCOPE.md` for scope matters, `SPEC.md`
(especially 4–6, 9–11, 12.1 and 13), `DEVELOPMENT_STANDARDS.md`, and A-ADR-002,
004, 006, 007, 012, 013, 014, 015, 022, 024, 025, 028 and 029 (with errata). The mockup
(`mockup/README.md`) is the starting point for the layout, and **not** a source of
data, scanner or actions. Each step ends with a stated acceptance test;
do not implement the next dependent step until the previous one works.

2. **Kartograf 0.8.0 contract (user decision 2026-10-18).** KA-1..KA-6
   go into Kartograf **0.8.0** (a prepared, not yet tagged
   release; Kartograf ADR-045, ARCH 3.3.1–3.3.2, CHANGELOG [0.8.0]);
   `kartograf.__version__` stays `"0.8.0"`, and `pyproject.toml` pins
   `kartograf>=0.8.0,<0.9` (A-ADR-024 erratum 1). In `.venv` install `../Kartograf`
   in editable mode from the branch `feat/archiwista-store-api` or after
   it is merged into `develop`. The number alone does not prove that KA is present (an older
   copy of 0.8.0 does not have it), so the contract test checks the symbols
   in `kartograf.__all__` **and** that `kartograf.__version__` falls within the
   range from the installed Archiwista's metadata; before the release
   repeat it against the tagged Kartograf 0.8.0. The contract (final
   names, ADR-045):
   - `list_segments(output_dir) -> list[str]` — sorted
     `<product>/<variant>` of all real second-level
     directories (without symbolic links and directories with a dot), including
     unrecognised ones; `iter_store(output_dir)` without a segment is a walk over
     this list.
   - `iter_store(output_dir, *, segment=None, units=None, skip_versions=None)
     -> Iterator[StoreEntry]` — `output_dir` is Kartograf's `--output` directory,
     that is the `data/` directory itself, not its parent. `skip_versions` is a set
     (`set`/`frozenset`) of relative paths of version **directories**
     `<segment>/versions/<hierarchy>/<label>_<sha8>`: each of their data
     files is returned as `kind="version"`, `sidecar=None`, `skipped=True`,
     with the label and `sha8` taken from the directory name; a missing sidecar in the listing still
     gives the problem `missing_sidecar`.
   - `read_sidecar(path) -> Sidecar`; `describe_segment(segment) ->
     SegmentInfo`; `file_footprint(entry, *, network=False, cache=None) ->
     Footprint | None` — source order `request` → `sheet` → `header` →
     `unit`; `cache` is a map owned by the caller
     (`MutableMapping[tuple[str, str], BBox]`, key `("teryt" | "ku" |
     "sm5", kod)`, value a native `BBox`), read also with `network=False`
     (without any request), filled only with
     `network=True`; for an entry without a sidecar (e.g. `skipped`) KA-4 reads it itself
     (1 open); `link_target(path) -> Path | None`;
     `pinned_transform(src_crs, dst_crs) -> PinnedTransform`.
   - `StoreEntry`: `kind` (`version`, `link`, `full_sheet`, `problem`),
     `segment`, `hierarchy`, `name`, `path`, `version_path`, `label`,
     `sha8`, `sidecar`, `problem`, `skipped`; `Sidecar` among others `dataset`,
     `dataset_key`, `country`, `request`, `data_year`, `data_date`, `unit`,
     `raw`; `SegmentInfo`: `segment`, `product`, `country`, `dataset_key`,
     `name`, `known`; `Footprint`: `native`, `wgs84`, `source`; `BBox` is a
     `NamedTuple` (`min_x`, `min_y`, `max_x`, `max_y`, `crs`).
   - Concurrency: any number of `iter_store` calls may run at the same time
     in separate threads — different segments or disjoint `units` batches
     of one segment; each generator is consumed by one thread. The same applies to
     `read_sidecar`, `describe_segment` and `link_target`; a `PinnedTransform`
     from memory can be shared.

   Do not import private modules and do not parse the `data/` layout in
   your own code; a missing KA or a deviation from the contract blocks the dependent step,
   it does not trigger a workaround.
3. **Scan: cost, parallelism and links.**
   - *Incremental = a full walk without re-reading known versions.*
     The scanner gives the adapter the versions known to the index
     (`ScanScope.known_versions`), and the Kartograf adapter turns them into
     `skip_versions` (the directories of those versions). A known version costs only
     a directory listing; link sidecars (standard path,
     `full_sheet/`) are always read, because the new current
     version follows from them; project manifests are read by `open_project`. A full scan (without
     `known_versions`) re-reads everything: it is the control scan once a
     day and "Przebuduj indeks" (Rebuild index). The cost per entry is in the table below the list of decisions.
   - *No KA-5 in the scan.* The current version of a slot is `StoreEntry.version_path`
     from the link sidecar (without hashing the content). Neither the scanner nor
     the adapter's `iter_entries` call `link_target`; KA-5 works only
     on demand (the `link_check` job from "Karta pliku" (File card)), because on a share without
     stable inodes it confirms the target with the SHA-256 sum of the whole file.
   - *Parallelism by segments.* The scan worker process takes the list of
     segments (`SegmentedAdapter.segments` → `list_segments`) and for
     each segment calls `iter_entries(scope=ScanScope(segment=…,
     known_versions=…))` in a bounded thread pool (`scan_threads`,
     default 8 — it limits I/O latency, not CPU); one generator per
     thread. Entries go through a bounded queue to a single write thread (batch:
     1000 entries or 1 s in one transaction). The metadata of new versions
     arrives together with the entry (`SourceEntry.meta`), so the scanner does not read the
     sidecar a second time. The footprints of new versions (in a full scan also of versions
     still without a footprint; `footprint` without network) are computed by a separate small pool
     (4 threads); the scan does not overwrite an existing footprint (versions
     are immutable). The time and the number of entries of each segment go into the
     job summary.
   - *View refresh* (`refresh_view`, ≤ 500 slots): `iter_entries`
     with `segment`, `units` and `known_versions`, with the units split into
     disjoint batches in the same pool; units from the sheet grid
     (`sheet_grid`) or from the footprints in the index.
   - *Erratum 1 (2026-10-19, step 13 measurements, `docs/reports/v0.1-measurements.md`).*
     Parallelism by segments alone was not enough on a share: 43%
     of entries (`nmt/pl_1992`) were read by one thread (incremental scan 342 s).
     Now on a share (`scan_threads` > 1) each segment of a
     `PartitionedAdapter` is split into parts (`partitions` →
     `list_partitions`, KA-1), and the pool reads the (segment, part) units
     heaviest first (weight: known versions of the part); writing is still done in one
     thread, the progress event and the segment time (the sum of the parts) come after the last
     part. A local disk is still read by one thread, whole segments at a time.
     `ScanScope.known_versions` is a mapping version directory → file names
     (`IndexWriter.known_versions`) only for directories whose files were all
     valid versions at the last read; the adapter passes
     them as a `skip_versions` mapping, so a known directory is no longer
     listed (cost 0 instead of a listing). A file removed or added
     inside such a directory is seen only by the full control scan
     (`full_scan_interval_h`, default 24 h; the time of the last one in "Magazyn" (Store),
     `/health`, `archiwista status`) — coordinator decision 2026-10-19.
     `refresh_view` takes the known directories of the view's slots and their neighbours
     from the same directory (`IndexWriter.slots_beside`): `bbox/` units
     no longer list several thousand version directories.
4. **Unit footprints requiring network: the `footprints` job.** The scan never
   uses the network. The adapter gives KA-4 a local cache of unit footprints
   (SQLite `<user_data_dir>/cache/kartograf/unit_bboxes.sqlite`; SPEC 5.6 rule:
   never `cache=True`, never on a share), so a scan without network
   assigns a footprint to new versions of already known units. Versions of units
   not yet known (TERYT from PRG, KU from RUIAN, SM5 sheet from the CUZK index —
   e.g. BDOT10k, EGiB, ZABAGED) stay "bez obrysu" (without footprint) with the reason `no_source`
   until a deliberate background job `footprints`
   (`POST /api/v1/stores/{store}/footprints`, with CSRF): it calls
   `footprint(entry, network=True)` for versions without a footprint and saves the footprints
   with source `unit`. In offline mode the endpoint refuses (`409`, code
   `offline_mode`) and the job does not start; the interface shows the reason
   for the missing footprint instead of geometry.
5. **Local coverage in a planar system.** "Lokalnie 83% obszaru" (Locally 83% of the area) is the area of the
   union of footprints of the product's current versions intersected with the area, divided
   by the area's size — computed with shapely in the planar system of the product's country
   (`SegmentInfo.country`: PL → EPSG:2180, CZ → EPSG:5514), never
   in WGS84 degrees (distortion of about 35% between the N–S and W–E axes
   at the latitude of Poland). The area and footprints are transformed by the pinned transformation
   KA-6 (`GeoAdapter.transformer`) after densifying the edges (shapely
   `segmentize`); a native footprint in the target system is not transformed.
   The R*Tree gives only candidates. A product without a country or a country outside the list →
   no percentage, with reason `no_planar_crs`; overlays are computed once. This is a local
   state, without suggesting availability at the source.

8. **Session, CSRF and CSP (A-ADR-012 erratum 1, SPEC 10.1).**
   - *Start token in the fragment.* `archiwista serve` opens
     `http://127.0.0.1:<port>/#token=<value>` (128 bits, single-use,
     valid for 10 min). The fragment does not reach the server, the access log or
the `Referer` header; `main.js` reads `location.hash`, sends the token
     with `POST /api/v1/session` and removes it from the address (`history.replaceState`).
     The Uvicorn access log is disabled by default, and when enabled it is
     filtered (redaction of `token=`).
   - *Session and a separate CSRF token.* The exchange sets the session cookie
     `archiwista_session` (`HttpOnly`, `SameSite=Strict`, `Path=/`) and a separate
     128-bit session CSRF token: in the `archiwista_csrf` cookie (without
     `HttpOnly`, `SameSite=Strict`) and in the response body;
     `GET /api/v1/session` returns `actor`, `csrf_token` and `expires_at`.
     `POST`/`PUT`/`DELETE` require a session and an `X-Archiwista-CSRF` header
     equal to the session CSRF token and to the cookie (double-submit) → otherwise
     `403 csrf_rejected`; without a session `401 session_required`.
   - *The `Origin` rule.* A present `Origin` must be the server address. A state-changing
     request with `Sec-Fetch-Site` (a browser) must have
     `Sec-Fetch-Site: same-origin` and `Origin`; a read with `Sec-Fetch-Site:
     cross-site` is rejected, while `none` (an address typed in or opened
     from a terminal) and `same-origin` pass. A client without `Origin`
     and `Sec-Fetch-*` (curl, an agent script) passes only with a session
     and, for a state change, with the CSRF header. The interface files (`/`,
     `/static/…`) do not require a session, `/api/*` does (except the token exchange,
     which does not require CSRF, but is subject to the `Host`/`Origin` rule).
   - *Further sessions and agents.* A one-time token valid for 5 min is issued by
     `POST /api/v1/session/tokens` (session + CSRF) or by `archiwista token`
     in the owner's terminal (the SHA-256 hash of the token in the local index);
     the user passes it to the agent outside the API.
   - *CSP.* `default-src 'self'; script-src 'self'; style-src 'self';
     worker-src 'self'; img-src 'self' data: blob: <P>; connect-src 'self'
     <P>; font-src 'self'; object-src 'none'; base-uri 'none'; form-action
     'self'; frame-ancestors 'none'`, where `<P>` is the sources (scheme, host,
     port) of the configured basemaps — only with `offline = false`.
     MapLibre fetches tiles through `fetch` (`connect-src`), so the basemap
     sources are there too; the worker is the bundled MapLibre 6 worker module
     (`maplibre-gl-worker.mjs`, run as a module from the same
     origin; in MapLibre 6 the ESM release replaced the separate CSP build —
     decision of 2026-10-18 at step 10a), without `blob:` in `worker-src`.
     Changing offline mode or the basemaps reloads the page
     (CSP applies to the document). In addition `Referrer-Policy: no-referrer`,
     `X-Content-Type-Options: nosniff`, no CORS.
9. **No producer data ≠ an empty result.** `not_installed`,

### Read cost per entry (KA-1, Kartograf ARCH 3.3.1)

| Entry | Cost |
|---|---|
| each directory | 1 × `scandir` (type from `d_type`, no `stat` of files) |
| segment list | 1 × `scandir` of the `--output` directory + 1 per product directory |
| `link`, `full_sheet` | 1 sidecar read (open+read+close), no `stat` and without opening the data file |
| new `version` | 1 sidecar read |
| known `version` (`skipped`) | 0 operations when its directory is in the `skip_versions` mapping ("settled" directory, erratum 1 of decision 3); in other directories the directory listing and sidecar read as for a new one |
| segment partitions (`list_partitions`, share only) | 3 × `scandir` (segment, `full_sheet/`, `versions/`) + up to 3 per split directory; per partition `stat`/`lstat` of the root, the segment and the key components |
| `missing_sidecar` | 0 opens (visible in the listing) |
| `invalid_sidecar` | 1 read |
| `stale_incoming` | `scandir` of `versions/.incoming` + `lstat` of the working directories |
| `unknown_segment`, `legacy_campaigns` | no additional cost (from the segment listing) |
| `units` scope | per unit `lstat` of each hierarchy level (protection against a symbolic link) for the standard path, `full_sheet/` and `versions/` + `scandir` of these three slot directories and of its version directories; only the entries of these units, without segment-level problems |
| `link_target` (KA-5) | never in a scan; on request it may read the whole file (SHA-256) |

The measurement in step 13 counts sidecar opens and compares them with this table.

## Contracts between steps

- **Source interface — `archiwista/sources/`** (step 1, `c74f8d4`; extended
  by step 2). State after step 1: `SourceAdapter` (attributes `producer`,
  `package`, `supported_versions`, `schemas`) with `probe(root) ->
  SourceState`, `iter_entries(root, *, scope: ScanScope | None = None) ->
  Iterator[SourceEntry]`, `read_meta(entry) -> EntryMeta`, `footprint(entry)
  -> Footprint`, `read_project(path) -> ProjectInfo`, `project_status(path)
  -> ProjectInfo` and the optional capability `SheetGridAdapter.sheet_grid(area,
  system, scale) -> SheetGrid` (state `unsupported` for producers without
  sheets). Types: `ScanScope(segment, units)`, `SourceState(producer,
  status, store, package_version, supported_versions, schemas, detail)`,
  `SourceEntry(producer, store, relative_path, kind, segment, slot_path,
  version_path, problem)`, `EntryMeta` (set, key, product, label
  and its source, data year/date kept separate from the download date, `sha256`, size,
  license, attribution, `source_files`, raw sidecar), `Footprint(location,
  wgs84, native, source, reason)`, `ProjectPin(store, version_path, sha256,
  task_id)`, `ProjectTask(task_id, command, options, status)`,
  `ProjectInfo(producer, store, path, name, tasks, pins, status, problem)`,
  `SheetGrid(status, sheets)`. Step 2 extensions — the only change to the contract
  of step 1, with an update of `tests/contract/test_source_protocol.py`:
  1. `ScanScope.known_versions: frozenset[Path] = frozenset()` — relative paths
     of versions known to the index; the adapter does not re-read their
     metadata.
  2. `SourceEntry.skipped: bool = False` (version known, metadata not
     read) and `SourceEntry.meta: EntryMeta | None = None` (metadata
     from the same pass; the scanner does not call `read_meta` a second time;
     `read_meta` remains for reading on demand).
  3. `footprint(entry, *, network: bool = False) -> Footprint`; the cache of
     unit footprints is kept by the adapter in `SourceContext.cache_dir`.
  4. Plugin factory `load(context: SourceContext) -> SourceAdapter`,
     `SourceContext(cache_dir: Path)` = `<user_data_dir>/cache/<producer>/`.
  5. Optional capabilities (modelled on `SheetGridAdapter`):
     `SegmentedAdapter.segments(root) -> tuple[str, ...]` (split for
     parallel scanning; the union of passes over segments = a pass without
     a segment; a producer without a split is scanned in a single pass)
     and `SegmentedAdapter.describe_segment(segment) -> SourceSegment`
     (`segment`, `product`, `country`, `dataset_key`, `name`, `known` —
     the `segments` table and the product's country from decision 5);
     `GeoAdapter.transformer(src_crs, dst_crs) -> CoordinateTransformer`
     (`transform(xs, ys)`, `description`, `accuracy_m`; the object can be
     shared between threads) and
     `GeoAdapter.countries(bbox_wgs84) -> tuple[str, ...]`;
     `LinkCheckAdapter.confirm_link(entry) -> Path | None` (on demand
     only).
  6. Additional fields, all with a default value (coordinator decision
     2026-10-18; the shape from step 1 still works): `EntryMeta` — `country`,
     `unit`, `survey_work_id`, `campaign` (campaign identifier),
     `edition`, `full_sheet`, `coverage`, `parent_request` (a stable
     text key of the files of one job), `horizontal_crs`, `vertical_crs`,
     `resolution`, `nodata`; `Footprint.native_crs` (the CRS of the
     `native` footprint); `SheetGrid.outlines` (the WGS84 polygon of each sheet
     in the order of `sheets`); `SourceEntry.handle` (the producer's own
     record, opaque to Archiwista and ignored in comparison:
     `footprint` of an entry from a scan does not read the sidecar a second time; an entry
     rebuilt from the index works without it at the cost of 1 read).

  The `store` field (`SourceEntry`, `EntryMeta`, `SourceState`, `ProjectInfo`,
  `ProjectPin`) is the producer directory of the store as text: the `root` passed
  to the adapter or the store indicated by the project manifest. The adapter
  resolves relative paths against it, so `read_meta`, `footprint`
  and `confirm_link` find the file from the entry alone; the index keys rows
  by the store identifier from the configuration and maps it to this directory through
  `StoreConfig`. `known_versions` are the paths of version files, and the Kartograf
  adapter skips their whole directories. Registry
  (`archiwista/sources/registry.py`): `load_registry(*, cache_dir=None) ->
  SourceRegistry` with `producers()`, `states()`, `state(producer)`,
  `adapter(producer)` and `probe(producer, root)`; `adapter` raises
  `SourceUnavailableError` or `SourceIncompatibleError` with a `state` field.
  An error of the producer's library leaves the adapter as
  `ProducerError(package, exception, message)` with the message unchanged,
  and an unreadable store as `SourceUnavailableError`.

  The Kartograf adapter is the only importer of `kartograf`; the rest knows
  only `archiwista.sources`, and the interface does not impose Kartograf's layout
  on a second producer (segments, sheets and links are
  optional capabilities).
- **Index — `archiwista/index/`** (step 5; scanner 6a; projects 7):
  `IndexQueries` returns typed `SlotPage` (`items`, `next_cursor`,
  location group counters), `SlotDetail`, `VersionDetail`, `FootprintPage`,
  `LocalCoverageReport`, `IndexStatus`, `StoreUsage`; `ProjectDetail`
  and `StoreSummary` are assembled by step 7 in `archiwista/services/` from these queries
  and the project tables. `IndexWriter` accepts protocol types, not Kartograf
  objects. Public keys: the short store name and the relative path of the
  slot/version. HTTP and the CLI use one `IndexQueries`; only the scanner and
  `refresh_view` walk the store tree. The `scan_projects` function
  (step 7) is called by scanner 6a in the write thread after a full pass over the whole
  store (the `scan` job of step 6b), with `AppSettings.project_dirs`
  and `AppSettings.stores`.
  State after step 5:
  - *Schema* (`schema.py`): `SCHEMA_VERSION` in `PRAGMA user_version`;
    a different version → `initialize` rebuilds the empty index in a single
    transaction (no migrations); WAL; `IndexUnsupportedError` when SQLite
    < 3.35 or without FTS5, R*Tree or JSON. The tables `jobs`, `job_events`
    and `session_tokens` are created by step 5, and steps 6b and 8 write to them.
  - *Write* (`IndexWriter(path)`, one thread at a time):
    `sync_stores({id: {producer: directory}})` (a store missing from the settings
    disappears from the index), `set_store_status(store, status, *, detail)`,
    `write_segments(store, producer, segments)`, a pass
    `begin_pass(store, producer, *, segment, slots, full) -> ScanPass` →
    `known_versions(segment)` (for `ScanScope.known_versions`) →
    `write_entries(batch) -> BatchResult` (batch = one transaction;
    `needs_footprint`: versions that are new or have no computed location, in a full
    pass also those without a footprint) → `write_footprints(store, [(entry,
    Footprint)])` (does not overwrite an existing footprint) → `finish_pass() ->
    PassSummary` or `abandon_pass()` (marks nothing). `finish_pass`
    marks versions not seen in scope as "brak pliku" (missing file) with a date, removes
    versions already missing in a full pass, clears unseen
    links, resolves problems, removes empty slots; a pass over the whole

### 8b. Permissions model
- **Goal (A-ADR-029, SPEC 4.3, 10.2):** a permissions model and its enforcement for

    (roles and groups from the state database); `authorize.py` with `can(principal, action,

    `users.manage`, `groups.manage`, `settings.write`, `store.write` —
    `require(...)` and `visible_projects(principal)`. Rules: `admin` sees
    all projects and manages accounts, groups, settings
    and the sharing of every project; the owner — their own project;
    `public` is seen by everyone, `users` — people in the entry, `group` — members of
    the group in the entry, `private` — only the owner; a project without an entry has

    `public`); an `agent` from a token acts with the roles and groups of the issuer

### 9c. Areas and local coverage over HTTP
- **Goal:** `archiwista/areas.py`, `archiwista/api/areas.py`:
  `POST /areas` — GeoJSON (WGS84) in the body or a file (GeoJSON, GPKG,
  zipped SHP with sidecar files). Limits (decision 9): body > 50 MB →
  `413 area_too_large`; an archive whose declared size after
  extraction exceeds 200 MB or whose member escapes the directory
  is rejected before extraction;

  coordinate system is converted to WGS84 by `GeoAdapter.transformer` (KA-6), countries
  from `GeoAdapter.countries`, area in a planar coordinate system. A copy of the file

  startup (the geometry stays in the index). `GET /areas/{id}` (geometry,
  `area_km2`, countries). `GET /local-coverage?area_id&product&store`: first
  `refresh_view` of the area's slots (≤ 500; units from the sheet grid or

## Risks and blockers

- **KA in progress.** KA-1..KA-6 with `list_segments` and `skip_versions` are
  being implemented in Kartograf on `feat/archiwista-store-api` (merge to
  `develop` after user approval). Steps 2, 4–7 and 9a–13 require this
  branch installed editable or merged; an older copy of 0.8.0 does not
  prove the presence of KA. The v0.1 release requires a tagged Kartograf 0.8.0
  with the public KA and a green contract test; until then, do not simulate
  the functions with private imports or a copy of the parser. State at the 0.1.0 release:
  KA (with `list_partitions` and the `skip_versions` mapping) is public
  in `kartograf.__all__` on the branch, contract test green; the branch merge
  and the `v0.8.0` tag await the user's decision, so 0.1.0 is installed
  with the Kartograf branch (`README.md`).
- **Test store without public writing.** The generator writes versions,
  sidecars and links itself (step 4); a divergence from the format is caught
  immediately by the Kartograf reader. If maintaining the generator turned out to be
  costly, report to Kartograf a requirement for public writing of a test
  version (SPEC 12), instead of duplicating more `data/` rules.
- **SMB.** Metadata and directory times can be inconsistent: the current version
  is determined by the link sidecar, KA-5 confirms it on demand, and a control
  full scan finds missed changes. The latency of directory operations
  is limited by a pool per segment; if the step 13 measurement does not meet the threshold, first
  measure the share of listing, sidecar reads and writing, then tune
  `scan_threads` — without lowering the thresholds and hiding failed measurements.
- **CZ and transformations.** CZ operations only through KA-6, never a default,
  approximate transformer.
- **Visibility filter skipped.** A new route or a query for projects
  without `visible_projects` exposes private projects; therefore the filter lives
  in the services and `IndexQueries` (not in the routers), and the visibility matrix
  from 8b covers every route returning projects or pins.
- **Online basemaps.** `Referrer-Policy: no-referrer` may not satisfy
  the rules of a tile provider requiring `Referer` (e.g. OSM servers); check
  deliberately (`-m live`) in 10b and, if needed, choose a gray
  basemap provider compatible with this policy, instead of loosening the `Referer` policy.
  Result of 10b: tile.openstreetmap.org without `Referer` returns an "Access
  blocked" image, so the default basemap is the gray BKG TopPlusOpen, and the policy
  stays (A-ADR-016, erratum 1; test
  `tests/integration/test_basemap_live.py::test_default_basemap_serves_tiles_without_referer`).
- **Frontend without types.** The risk is mitigated by JSDoc, Playwright and the OpenAPI
  contract; bundled libraries must be verified under CSP, offline and with a license
  compatible with MIT.
- **Environments.** An SMB share and a live 0.8.0 store require a separate,
  explicit `<data-dir>`; the absence of these environments means an unclosed
  criterion, not automatic success.
