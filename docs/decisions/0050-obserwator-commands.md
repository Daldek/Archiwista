# ADR-050: Obserwator's commands in Archiwista: the store-writing catalog, national archives, the whole-store rescan

**Date:** 2026-11-05
**Status:** accepted (the author approved the plan [`docs/plans/2026-11-05-obserwator-actions.md`](../plans/2026-11-05-obserwator-actions.md) on 2026-11-05 by starting its implementation; decisions A1 to A5 of that plan, recorded here as its A7); amends ADR-024 (Obserwator as an optional plugin: it now also offers commands) and ADR-049 decision D5 (IMGW pins are checked, re-pinned and restored)

**Context:** The Obserwator plugin (ADR-024, ADR-032) read the store only: stations, series and their coverage, the station card. A person fetched IMGW-PIB data with Obserwator's own command line and Archiwista indexed what it found; `archiwista commands list` named Kartograf's commands alone, no job could fetch IMGW data, and a project's IMGW pins could be verified and exported but not checked, re-pinned or restored. Obserwator `1ee5457` (pinned, Nogat's release set `candidate-1`) offers in `obserwator.__all__` what Kartograf's commands offer: `data_commands`, `list_commands` and `command_schema` with Polish and English texts, `parse_command`, `validate_command`, `format_command`, `check_command` (the plan `obserwator-plan/1`), `run_command` with `on_progress`, `on_notice` and `cancel`, and `command_for_version` (IMGW-21). IMGW-PIB's archives are national files: a year or a month of the whole country per file (the registry's `archive_scope` `country`), so an area chooses nothing in a download; it only filters stations in the views. Obserwator scans only its whole store (`iter_store`), skipping the versions the index knows.

**Options:**
- Which commands the catalog offers: A) the commands of Obserwator's catalog that write its store, `store sync`, `store catalog` and `series build`; B) Obserwator's whole catalog, as Kartograf's. Rejected: most of it reads (`series read`, `current hydro`) or writes plain files outside every store (`store export`, `series export`), and the jobs refuse both (`no_store`, `no_check`); C) A plus `pmaxtp sync` and `datasets download --root`. Deferred: no view of Archiwista reads PMAXTP cells yet, and `datasets download --root` duplicates `store sync` without the series.
- Where a position and a file of a run are: D) the slot's directory below the store root (`archives/versions/<server path without its suffix>`, `series/versions/<slug>`, `stations/versions[/<catalog>]`), the path the index keeps an Obserwator slot under, with the version as `version_path`; E) the version's file alone. Rejected: a plan's position has no version yet, so a plan, a claim (ADR-047) and a run's file of one slot would not meet, and a pin by its slot (ADR-049) would not find its current version.
- How the index learns what a run wrote: F) an incremental scan of the producer's whole directory after any run of a producer that reads only its whole directory (`SegmentDescriptionAdapter` without `SegmentedAdapter`), the scope of every path being the whole store (`ScanScope()`); G) the units of a run's files, as for Kartograf. Rejected: Obserwator refuses a scope of units, and the series and the station catalog of a run are read only after a pass over the whole store.
- An area for a pasted command: H) refused with `no_area_option` (`AreaCommandAdapter`); the map's pasted line goes as written while the area was only the field's default; I) the area silently dropped. Rejected: a person who chose an area is told nothing.
- Where a person starts a download: J) „Polecenia producenta” of the Store view, a form read from the catalog for each producer of the store whose data no area chooses (no availability at the source), and a line pasted in the map's step „U źródła”; both open the plan window; K) a form in the station views. Deferred: a station chooses no archive either, and the Store view is where a store's data are kept up to date.

**Decision:** A, D, F, H and J.

1. **The catalog (A1).** `ObserwatorAdapter` implements `ActionAdapter` with `obserwator.__all__` only (`src/archiwista/adapter/obserwator/actions.py`). `commands()` returns `store sync`, `store catalog` and `series build` in the order of `data_commands`, described by `command_schema(lang=…)` in the call's language. Their options are the schema's without what Archiwista names beside them: `root` (the configured store's, never a request's), the plain mode (`output_dir`, `force`) and `plan`. `parse` moves Obserwator's `--root` from the options into `CommandCall.run`; `format` puts it back and keeps only Obserwator's flags of a run (`check`, `json`, `lang`). A refusal is `ProducerError` with Obserwator's code, its text and hint in the call's language and its `details` (`option`, `value`, `allowed`).
2. **The plan (A1).** `check` calls `check_command` with the store's root; the positions of `obserwator-plan/1` are each archive of `items` (its `content_length` as the size, `Last-Modified` as the label at the source, the version's label as the local one), each dataset's series of `series_state` (`outdated` is `newer`) and each other action of `actions` (a root a run refuses is a `conflict` with its reason). The whole plan is kept as the `document`.
3. **The run (A1).** `run` calls `run_command`; a kept plan of `store sync` goes back as Obserwator's plan file in the plugin's cache directory (outside every store, removed after the run) in place of the options it stands for. A position whose source changed since the plan fails as `conflict` with `stale_plan`. An interrupt (`KeyboardInterrupt`) goes through; Obserwator publishes each version whole, so an interrupted run leaves no part of one. Without a plan Obserwator downloads what is new or missing at the source, newer versions included: it has no mode that keeps the stored ones, so `upgrade` changes nothing. `narrow` removes the archives to download that another job claimed from the entries and from the document's `items`; the series of the plan stay in the document (a run builds an unchanged series as `unchanged`).
4. **No area, no availability (A2).** `availability_products()` is empty and `availability` refuses with `no_availability`; `with_area` refuses every command with `no_area_option`.
5. **Jobs and projects (A3).** The jobs take the producer from the call or the pin. What assumed Kartograf in the rescan of `jobs/worker.py` is generalised (`reads_whole`, F): a producer that reads only its whole directory is read again by an incremental `scan_store` of that directory, with the projects' areas, after every run; the others as before. The project jobs `project_check`, `project_repin` and `project_restore` run IMGW pins through `command_for_version` and this catalog, with no code of their own for Obserwator.
6. **The interface (A4).** The plan window is the producer's own already; „Polecenia producenta” of the Store view (`views/store-commands.js`) and the map's pasted line open it for Obserwator's calls; texts are Obserwator's Polish ones from its catalog.
7. **No change of Obserwator (A5).** What Obserwator lacks is a `request` in its repository (DEV-17.5), never a workaround here; the places of plan positions follow its store layout, and contract tests compare them with the versions it writes.

**Consequences:** Obserwator's three store commands appear in `GET /commands`, `archiwista commands list`, the plan window, the Store view and the project card's actions. A store of Kartograf and Obserwator answers each producer's commands from its own directory. The tests: `tests/contract/test_obserwator_actions.py` (Obserwator's real check and run, its HTTP layer stood in for by its own fixture archives, `tests/fixtures/obserwator_http.py`; one `live` test of `pl.imgw.hydro_daily` 2024), `tests/integration/test_obserwator_jobs.py` (real workers, `tests/fixtures/obserwator_worker.py`: check, download with a pin, project check, restore, re-pin) and `tests/e2e/test_store_commands.py`. A plan of `store catalog` has no position to download when a catalog exists (the public API gives no freshness signal: `unverifiable`), so a run of that plan downloads nothing; a refresh of the catalog runs without a plan.
