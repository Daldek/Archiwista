# ADR-056: Obserwator's raw root and data root in a store

**Date:** 2026-11-14
**Status:** accepted (the author approved Nogat's plan [`2026-11-12-station-data-and-analyses`](https://github.com/Daldek/Nogat/blob/main/docs/plans/2026-11-12-station-data-and-analyses.md) on 2026-11-13: its D5 and step R2, which adopt Obserwator's [ADR-017](https://github.com/Daldek/Obserwator/blob/0591b82/docs/DECISIONS.md#adr-017-the-data-root) in Archiwista); amends ADR-032 decisions 5, 6 and 8 (the marker, nesting, the current version), ADR-033 (the default roots), ADR-049 decision 7 (a project's store) and ADR-050 decisions 1, 2 and 5 (Obserwator's commands)

**Context:** Obserwator's store was one root, marked by `obserwator-store.json` (`obserwator-store/1`), that held both the archives Obserwator downloads and the series and station catalogs it builds from them. Archiwista configured it in the field `obserwator` of a store (ADR-032), ran `store sync`, `store catalog` and `series build` in it (ADR-050) and indexed every version below it. Obserwator, pinned at `0591b82`, splits it into two roots ([ADR-017](https://github.com/Daldek/Obserwator/blob/0591b82/docs/DECISIONS.md#adr-017-the-data-root), Nogat ECO-059):

- the **raw root**: the marker `obserwator-store.json` (`obserwator-store/1`, unchanged), `archives/` and `pmaxtp/`. `store sync` downloads into it, and it writes raw data only ([ADR-015](https://github.com/Daldek/Obserwator/blob/0591b82/docs/DECISIONS.md#adr-015-raw-data-only-in-store-sync-station-sources-archived-catalogs-offline));
- the **data root**: the marker `obserwator-data.json` (`obserwator-data/1`), `series/`, `stations/` and `analyses/`. Obserwator builds it offline from the raw root (`series build`, `store catalog`, its analyses).

A root of the other kind is refused by Obserwator with `details.reason="wrong_root"` (ADR-017 D3). Each kind has its own default (ADR-017 D5): the data root is `OBSERWATOR_ROOT`, `[obserwator] root` of `nogat.toml`, else `<data_dir>/obserwator`; the raw root is `OBSERWATOR_RAW_ROOT`, `[obserwator] raw_root`, else `<data_dir>/obserwator-raw` (`store_root(kind="data" | "raw")`). The kind of a version is the first part of its path (`archives/`, `pmaxtp/`: raw; `series/`, `stations/`, `analyses/`: data; ADR-017 D6), and paths below each root are the ones the combined store had. A store written before ADR-017 is not converted: it is split once by a copy with hard links (ADR-017 D8, Obserwator's `docs/USAGE.md` ["Splitting a store"](https://github.com/Daldek/Obserwator/blob/0591b82/docs/USAGE.md#splitting-a-store)). Nogat's plan gives the raw root's downloads to Archiwista and the data root to Obserwator (D5): Archiwista orders the downloads into the raw root and reads the series and catalogs from the data root, and `series build` and `store catalog` leave its actions.

**Options:**
- How the settings name the two roots:
  - A) `obserwator` keeps naming the raw root (the meaning it has had for every config: the directory of `obserwator-store.json` that `store sync` writes), and a new field `obserwator_data` names the data root.
  - B) `obserwator` becomes the data root and a new field names the raw root. Rejected: a silent change of meaning of a saved field; every existing config would point the data reader at a raw root.
  - C) One parent directory with fixed child names by convention. Rejected: Obserwator lets each root lie anywhere (e.g. on another disk) and defines no such convention.
  - D) Two stores, one per root. Rejected: the series of a store and the archives they come from would be two stores; scans, pins and the map would split one provider's data.
  - E) Two producer ids (`obserwator`, `obserwator-data`). Rejected: two plugins of one package, and the producer and paths of pins would change, so existing project pins would break.
- How the index reads them:
  - F) One producer `obserwator`, one scan pass over both directories, each path relative to the root of its first part (ADR-017 D6): paths unchanged, no index schema change.
  - G) Paths prefixed with the root they lie in, or a column for it. Rejected: every indexed path and every project pin would change, for a fact the first part of the path already gives.
- Which of Obserwator's commands Archiwista runs:
  - H) `store sync` only, into the raw root.
  - I) `store sync`, `store catalog` and `series build` as before (ADR-050). Rejected: Nogat's plan D5 and Obserwator's ADR-015 and ADR-017 give the builds of the data root to Obserwator, offline; Archiwista keeps the data root read-only.

**Decision:** A, F and H, with a probe of each root by its kind (decisions 3 and 4).

1. **Settings.** Each `[[stores]]` entry of `config.toml` (and `GET`/`PUT /api/v1/settings`) keeps `kartograf` (Kartograf's store root) and `obserwator` (meaning unchanged: Obserwator's raw root) and gains `obserwator_data` (a path or `null`: Obserwator's data root). At least one of the three directories is required. `StoreConfig.directories()` lists the configured directories in the order of `STORE_DIRECTORIES` (`kartograf`, `obserwator`, `obserwator_data`), each a `StoreDirectory` with its settings field, producer and whether it is a data root; `roots()` keeps the producers' store roots (Kartograf's store, Obserwator's raw root), the roots their commands write.
2. **One producer, two directories** (amends ADR-032 decision 8). The index knows one producer id, `obserwator`, and reads both of its directories in one scan pass. Every indexed path is relative to the root of its first part: `series/`, `stations/` and `analyses/` lie in the data root (`archiwista.sources.markers.DATA_TREES`), anything else in the raw root (`directory_field`, `StoreConfig.root_of(producer, path)`). The paths are the ones of the combined store, so existing project pins stay valid. The index schema does not change: the JSON column `stores.roots` is keyed by settings field (`kartograf`, `obserwator`, `obserwator_data`; `StoreConfig.directory_paths()`). The current version of a keyed slot (ADR-032 decision 8) is asked of the root its slot path lies in, and the station catalogs and series indexes (ADR-032 decisions 11 and 12) are read from the data root.
3. **A probe per kind** (amends ADR-032 decision 5). `SourceAdapter.probe` judges a store root (Obserwator's raw root); the new optional capability `DataRootAdapter` (`probe_data(root)`, `default_data_root()`, `sources/protocol.py`) judges a data root. A root of the other kind is `incompatible` with the new reason `wrong_root`, and so is a store written before ADR-017 entered as the data root (its marker is the raw root's). The registry takes the kind as a flag: `probe(producer, root, data=)`, `probe_root(adapter, root, data=)`, `read_default_root(registry, producer, data=)`; a data root of a producer without the capability is an `error` state.
4. **Settings validation** (amends ADR-032 decision 6). `validate_settings` probes each new or moved directory by its kind, so a problem names its field (e.g. `stores[0].obserwator_data`) and a directory of the wrong kind is refused with the reason `wrong_root`. No root nests in another (DEV-19.14): `check_nesting` compares every directory of the settings, raw and data roots included, and `obserwator-data.json` counts as a store marker when ancestors and the levels below a directory are searched (`sources.markers.marker_in`).
5. **Commands** (amends ADR-050 decisions 1, 2 and 5). Archiwista runs only Obserwator's `store sync`, into the raw root (`STORE_COMMANDS` of `adapter/obserwator/actions.py`); `series build` and `store catalog` leave Archiwista's catalog, and a plan's positions are the archives of the raw root (`archives/versions/<server path without its suffix>`). `command_for_version` of a data-root version (a series, a station catalog, analyses) is refused as `unsupported` with the reason `command_not_rebuildable` and Archiwista's text `source.obserwator_data_version`, which names the Obserwator command that builds it; so project pins of series and catalogs show as `not_checkable`, and pins of archives are checked, re-pinned and restored as before.
6. **Default roots (ADR-033 extended).** The items of `GET /api/v1/sources` keep `default_root`, the producer's default store root (for Obserwator its default raw root, `store_root(kind="raw")`), and gain `default_data_root` of the same shape (`path`, `source`, `name`, `exists`, `marked`, `message`): the producer's default data root (`store_root(kind="data")`), `null` for a producer without a data root (Kartograf) or an unavailable plugin. The wizard offers each under the empty field of its kind (`obserwator`, `obserwator_data`) as ADR-033 decision 2 says, and `archiwista doctor` reports the default data root beside the default store root. As before, an offer is never entered without the person's click and never used.
7. **Project files and reachability** (amends ADR-049 decision 7). A project file keeps one directory per producer; for Obserwator it names the store by its raw root, else its data root (`StoreConfig.producer_root`), and `match_store` matches a project's directory to any of the producer's directories, so a file written with the combined store's root keeps matching when that directory becomes one of the two roots of the split. Every read of a version (a preview, a copy path, an export, a project's `verify`, a pin's call) takes the directory its path lies in, probed by its kind. A scan judges each directory apart: a directory that reads nothing while the index holds entries in it is an unmounted share (`scan.store_empty`), and the scheduler counts a store with entries unreachable only when all its directories are empty, since an empty raw root beside a data root is a store nothing was downloaded into yet.
8. **No change of Obserwator.** The rules of the two roots, the path rule and the split are Obserwator's (ADR-017); Archiwista converts no store and reads no store as both kinds.

**Consequences:**
- Existing configs keep working: their `obserwator` is read as the raw root, and nothing is renamed.
- An old combined store configured as `obserwator` is read as a raw root: its `series/` and `stations/` are reported as `unknown_entry` problems (Obserwator's `iter_store`, ADR-017 D2) and its series and stations are not shown until the person splits it as Obserwator's `docs/USAGE.md` "Splitting a store" says and sets `obserwator_data` to the new data root. Entered as `obserwator_data`, it is refused (`wrong_root`).
- A store with only `obserwator_data` is valid: Archiwista reads its series, catalogs and stations; `store sync` of it is refused, as for any store without the producer's store root (`store_without_producer`).
- The deployed team server (one store with an empty raw root) needs no change.
- The tests' fixture builds both roots (Obserwator's `build_fixture_store(root, *, data_root)`, ADR-017 D9) and configures both fields.
