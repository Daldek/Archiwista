# ADR-034: The producers' commands as data, an optional capability of the adapters

**Date:** 2026-10-25
**Status:** proposed (done on the topic branch `feature/kartograf-data-output`, step A1 of the plan `docs/plans/2026-10-25-archiwista-next.md`, whose approval is delegated; accepted when the author approves and merges the branch)

**Context:** v0.3 "Actions" (SPEC 13, SCOPE stage 4) needs the producers' commands before anything runs: the forms and the product list (KB-1), a pasted command (KB-2, UC-15), the check of a form field without network (KB-3) and the `kartograf …` line of the plan window and of `polecenia.sh` (KB-4). Kartograf delivers them as data at the pin `c31ca04c`: `list_commands()` (`kartograf-command-list/1`) and `command_schema(command)` (`kartograf-commands/1`, with `i18n.pl`, `effects`, examples and the `path_role` of path options) describe all 45 commands of its catalog, and `parse_command`, `validate_command(…, root=)`, `format_command(…, run=)`, `check_command` and `run_command` work on every one of them (the last two return the envelope `kartograf-result/1`). The store root and the flags of a run are keyword arguments beside the options (`root`, `output_dir`, `update`, `plan`, `workers`, `summary`, and `check` chooses `check_command`), and `validate_command` refuses `root` for a command without a store. IMGWTools 3.0.0 has the same layer with another shape: `list_commands(*, lang)`, `command_schema(command, /, *, lang)` (JSON Schema with `x-imgw-*`), `validate_command(command, /, *, options)` that returns the normalised options, `format_command(command, /, *, options)`, `check_command` and `run_command` with `cancel`; the store root is `options["root"]`, and it has no `parse_command`. Archiwista's layers above `sources/` must not know either shape (A-ADR-014, A-ADR-024).

**Options:**
- A) An optional capability `ActionAdapter` of the source interface with producer-neutral types; each adapter converts its producer's documents.
- B) Serve Kartograf's documents and error reports as they are. Rejected: a Kartograf class or document would leave `adapter/kartograf`, and the IMGW source (v0.5) would need a second set of routes.
- C) Keep Archiwista's own description of the options and rules. Rejected: it is the copy of Kartograf's rules that KB-1 exists to avoid.
- D) Let the store root be an option like any other. Rejected: a form, a pasted line or an agent could then point a producer at any directory, or leave it out and let the producer's default root stand in (Decision 1 of the plan).

**Decision:** A.

1. **Types and protocol** (`sources/types.py`, `sources/protocol.py`). `CommandInfo` (producer, `command` as `<group> <verb>`, group, summary and description in the call's language, the options of a call, `read_only`, `writes` (`none`, `add`, `replace`, `delete`), `network`, `check`, `store`, examples), `CommandOption` (name, JSON type, required, description, `choices` with their meanings, default, bounds, item type, the `group` of mutually exclusive options and the `path_role` `input` or `output`), `CommandChoice` and `CommandCall` (producer, command, `options` in the producer's JSON form and `run`: what a line gives beside the options, by the names of the data-output convention where it has them). `ActionAdapter` has `commands()`, `parse(line)`, `validate(command, options, *, root)` and `format(call)`; none of them uses the network or writes. A4 and A5 add the plan and the run with their own types (`ActionPlan`, `ActionResult`).
2. **The store root is never an option of a call.** `CommandInfo.store` says that a command works on a store, `CommandCall.run["root"]` carries the root a line names and `validate` takes the root by name. The Kartograf adapter passes `root=` for a command whose schema has the option with the path role `root` (and only then: Kartograf refuses it elsewhere); an adapter of a producer with IMGWTools' shape puts it into `options["root"]` (the stand-in producer of the tests does). A command on a store without its root never reaches the producer (`ValueError`, a program error), so its default root cannot stand in.
3. **Kartograf's catalog** (`adapter/kartograf/actions.py`) is `list_commands()` in its order and `command_schema()` of each command. The options of a call are the options of the schema without the names `run_command` and `check_command` take by keyword and `check`, read from their signatures, so a flag of a run that Kartograf adds stays out of the forms. The summary and the description are Polish for a Polish call (`i18n.pl`); the descriptions of the options and the meanings of their values are Kartograf's English, as it has no other.
4. **A refusal is the producer's.** The Kartograf adapter turns an error of these functions into `ProducerError` from Kartograf's own `error_report` in the call's language: its registry code (`validation_error` is `400`), its text and hint unchanged, what it names at the top of `details` (`option`, `options`, `allowed`), its own reason in `details.kartograf.reason` beside `exception` and `message`, and `details.reason` `kartograf_error`. `ProducerError` gains the keywords `code`, `hint` and `details` for it; a code Archiwista's registry lacks stays `data_error`.
5. **What Archiwista adds is checked before the producer** (`services/commands.py`, shared by the API and the command line). `validate` takes a command of the producer's catalog only (`CommandRequestError`, reason `unknown_command`: an operation id would otherwise bypass the next two rules); it refuses an option with a `path_role` given in the request (`403 forbidden`, reason `path_outside_root`, `details.option`), because Kartograf's check of a download opens its geometry file in the server's process (SPEC 10.1); and for a command on a store it names the root of a configured store's producer directory (`store_required`, `store_without_producer`, `404` for an unknown store). A producer whose plugin is not available refuses its own commands only (`503`, reason `source_unavailable`), and one without the capability refuses them as `unsupported` (reason `no_commands`). The catalog of all producers leaves both out; `GET /sources` says why.
6. **Tests** run Kartograf's real catalog under the canary of the default roots and a socket guard (`tests/fixtures/network.py`); a stand-in producer with IMGWTools' shape (`tests/fixtures/action_source`, registered by an entry point as `second_source` is) records the options it receives, so a test sees the configured store as its `options["root"]` and sees that a refused request never reached it.

**Consequences:**
- The IMGW adapter implements the capability in v0.5 from `list_commands(lang=…)`, `command_schema(command, lang=…)` (the properties become `CommandOption`s, the option with `x-imgw-path-role` `root` becomes `store`), `validate_command`, which returns the normalised options, and `format_command`. IMGWTools has no `parse_command`: its adapter refuses `parse` until it has one (a request), and does not parse IMGW lines itself.
- The routes and commands of step A1 commit 2 (`GET /commands`, `POST /commands/parse`, `/validate`, `/format`, `archiwista commands …`) are thin over `services/commands.py`.
- Kartograf's example of `project add` (`kartograf project add gleby soil hsg --sheet N-34-130-D --depth 0-5cm`) is not the line `format_command` writes for its call (`--depth` comes first), so the contract test reads every example back into the same call instead of comparing the text; the example is reported to Kartograf (plan "Requests").
- Validating a download with an area from a file needs the copy Archiwista keeps of the area (SPEC 6.3); until a later step maps an area id to that copy, `validate` refuses the path and the area is a sheet or a box.
