# ADR-037: The run of a command: the capability, the files it reports and their scan scope

**Date:** 2026-10-26
**Status:** proposed (done on the topic branch `feature/kartograf-data-output`, step A5 of the plan `docs/plans/2026-10-25-archiwista-next.md`, whose approval is delegated; accepted when the author approves and merges the branch)

**Context:** "Pobierz…" runs what the plan window showed (SPEC 13 v0.3, criteria 4, 5 and 7). Kartograf runs a command with `run_command(command, options, *, root, update, plan, cache, on_progress, on_notice)`, whose envelope `kartograf-result/1` holds `kartograf-download/1`: `files[]` (`unit`, `country`, the absolute standard `path`, `size_bytes`, `sha256`, `status` `new`, `unchanged` or `relabeled`, `label`, `version_path`; plain `written` and `replaced` only with `output_dir`), `failed[]`, `stale[]` (a position of the plan the source changed since) and `items[]` (AGI-4.2). A run with `update="upgrade", plan=…` runs a plan of `check_command`, the one the person saw. `DownloadProgress` (`current`, `total`, `sheet`, `status`, `message`) mixes counts: the units of a run, but also the flights of one sheet (`campaigns`, `campaign`) and one transfer (`start`, which may name a text, not a unit). After a run the index must show the new versions without a scan of the whole store, so Archiwista needs to know which slots to read again.

**Options:**
- A) The worker scans the whole store after a run. Rejected: a pass over every segment for a few files, and a store's index is written by one scan at a time.
- B) The capability reports the files below the root, and the adapter maps a file's standard path to the scan scope that reads its slot again (`scope(path)`: its segment and one unit); the job rescans those scopes.
- C) The capability reports the segments and units of the run itself. Rejected: Kartograf reports the units of a request (a sheet code, a LAZ file name, a TERYT, box coordinates), not always a unit its own store reader takes, and nothing of a plan's positions.

**Decision:** B.

1. **Capability** (`sources/protocol.py`). `ActionAdapter` gains `run(command, options, *, root, plan=None, on_progress=None, on_notice=None) -> ActionResult` and `scope(path) -> ScanScope`. `ActionResult` (`sources/types.py`) is the producer's result without its classes: `producer`, `command`, `root`, `status` (`ok`, `partial`, `failed`), `files` (`ActionFile`: `path` and `version_path` below the store root, `unit`, `status` of `FILE_STATUSES`, `size_bytes`, `sha256`, `label`), `items` (`ActionItem`: `id`, `status`, `code`, `reason`, `message`), `notices` and the `schema` of the producer's own result; `failed` lists the items that failed. `ActionProgress` (`current`, `total`, `unit`, `status`, `message`) counts the units of a run. A unit that fails is an item, not an error; an interrupt (`KeyboardInterrupt`) goes through the run, which publishes each version whole.
2. **Kartograf** (`adapter/kartograf/actions.py`). `run_command` gets `root=` the configured store's directory, Archiwista's own `MetadataCache` (D5), never `output_dir`; with a plan `update="upgrade", plan=UpdatePlan.from_dict(plan.document)`, without one no `update` (the versions the store holds are kept). `files[]` are read from the JSON of the envelope, the documented contract; a file outside the root (also through `..`) or with a plain status is a `BrokenContractError` (`data_error`, reason `broken_contract`): Archiwista asked for neither. A command whose result is no download (`store init`) has no files. Progress events that count something other than units (`start`, `campaigns`, `campaign`) keep the last counts of the units, and only an event about a unit names it.
3. **Scope.** Kartograf's standard path is `<product>/<variant>/<slot directory>/<file>`, and `iter_store` reads a unit `<slot directory>/<stem>` as the files of that stem in that directory, whatever kind of unit the slot is of. `scope(path)` is the segment `<product>/<variant>` and that one unit (the stem is the name without its last suffix). A contract test reads every standard path of the generated store this way and finds that file, and no file of another slot.

**Consequences:**
- A producer that offers its commands (`ActionAdapter`) must also run them and name the scope of its files; the stand-in of the tests does (`tests/fixtures/action_source`), the IMGW adapter will in v0.5.
- `files[]` keep Kartograf's statuses: `unchanged` also stands for its `local` and `reused`, so a run that fetched nothing again says so per file.
- A plan's positions have paths below the root too, so their scopes are known before a run.
