# ADR-057: Nogat's server logs in `<state_dir>/archiwista/logs`

**Date:** 2026-11-14
**Status:** accepted (Nogat ECO-066, DEV-12.4 to DEV-12.9 and DEV-18.2, Nogat `develop` `f370afe`, adopted as Hydrolog's ADR-0037 and Obserwator's ADR-019 adopted them); amends ADR-053 (a fifth key of `nogat.toml`)

**Context:** `archiwista serve` logged through Uvicorn: its own messages at the level of `--verbose`, `--quiet` or `ARCHIWISTA_LOG_LEVEL` on standard error, and with `--access-log` Uvicorn's access line, which names the client's address, its `token=` values hidden by `TokenRedactionFilter`. It printed the one-time address `http://127.0.0.1:<port>/#token=…` on standard output, which a service manager keeps in its journal. A job process wrote its log to the job's own log only (`<jobs>/<id>.log`, shown by the API and „Dziennik”), a render process to nowhere (its standard error is discarded). Nogat's ECO-066 gives every server of the ecosystem one convention, which Nogat checks: three logs (access, application, lifecycle) in the format `nogat-log/1` (`schemas/log/record-1.schema.json`), daily files in `<state_dir>/<project>/logs` that the server deletes 14 days after their date, only lifecycle records and errors reduced to their type on standard error, no client address, the User-Agent as its class, the values of credentials and personal parameters dropped from a query, a request id never sent to the client, and one implementation, Nogat's `standards/reference/nogat_logging.py`, copied byte for byte (DEV-15.6).

**Options:**
- A) Keep Uvicorn's access log behind `--access-log` and add Nogat's records beside it. Rejected: two formats, and Uvicorn's line names the client.
- B) Nogat's module in the server only. Rejected: a failure in a render process would leave no trace, and a job's warnings would stay in the job's log, which is deleted with the job.
- C) Nogat's module in the server, and the job and render processes writing their warnings and errors as app records to the same directory, without deleting anything.

**Decision:** C.

1. **The copies.** `standards/reference/nogat_logging.py` is copied unchanged to `src/archiwista/nogat_logging.py` and `schemas/log/record-1.schema.json` to `schemas/nogat/record-1.schema.json`, both from Nogat `f370afe` (`schemas/nogat/README.md` gives their SHA-256). A change is made in Nogat and copied again.
2. **`state_dir`.** A fifth key of `nogat.toml`, `[archiwista]` before `[nogat]`, read like `data_dir` (no `NOGAT_STATE_DIR`: ADR-053), default `platformdirs.user_state_path("nogat")` (`~/.local/state/nogat` on Linux). The logs lie in `<state_dir>/archiwista/logs` (`AppPaths.state_home`, `AppPaths.logs_dir`); `archiwista doctor` names the directory and the key that gave it. An `AppPaths` built without `state_home` keeps the logs in its data directory, so a test never writes into the user's state directory.
3. **The server.** `serve_main` makes a `ServerLog` (`archiwista.logs.server_log`) whose lifecycle and reduced records go to its standard error, wraps the application in `AccessLog`, outside every middleware, so the refusals of `SecurityMiddleware` are logged too, with `ACCESS_QUIET = r"^/static/|/tiles/\d+/\d+/\d+\.png$"` (the interface's files and the map tiles of the previews and the layers are logged only from status 400), and serves inside `archiwista.logs.server_logging`: the record `start` with `origin` alone, never the token or the address that carries it; the app records of `warning` and above of every logger; `stop` once the scheduler, the jobs and the render pool have stopped. Uvicorn runs with `log_config=None` and `access_log=False`.
4. **The level.** `--verbose`, `--quiet` and `ARCHIWISTA_LOG_LEVEL` keep the level of the command line's log on standard error (DEV-12.2). `archiwista serve` follows it until it serves; then the package's handler is set aside and the application log keeps `warning` and above whatever the level (DEV-12.7). A job's own log keeps the level of the variable.
5. **The workers.** A job process gets the directory in its `JobSpec` (`log_dir`, job protocol 15), a render process as `--log-dir` (the render pool's and the `preview` job's builds); `archiwista.logs.log_to_server` adds a handler that writes their records of `warning` and above as app records with `ServerLog.application`, its stream dropping the reduced errors, so the job's own log keeps its lines unchanged. They never call `ServerLog.start`: only the server deletes files and writes lifecycle records.
6. **The address.** `archiwista serve` prints the one-time address, and in team mode the origin, only when standard output is a terminal (`isatty`); elsewhere the browser's launch file and `archiwista token` give an address.
7. **What goes.** `--access-log` (and its message), `uvicorn_log_config`, `TokenRedactionFilter`, `redact_tokens`, and the `log_level` and `access_log` parameters of `serve_main` and `AppServer`.

**Consequences:** The access log of a running server is `~/.local/state/nogat/archiwista/logs/access-YYYY-MM-DD.jsonl`, read with the README's command `jq -cs 'sort_by(.time)[] | select(.kind != "access" or .status >= 500)' <state_dir>/archiwista/logs/*.jsonl`; the journal of a service shows only starts, stops, deletions and errors by type. A command line or unit that passes `--access-log` must drop it (`docs/CHANGELOG.md`). A job or a preview a command runs in the foreground also writes its warnings and errors to the logs directory, which only a running server prunes. Uvicorn's own `503` beyond `LIMIT_CONCURRENCY` never reaches the application and is not logged.
