# ADR-058: A project's files take the permissions of their folder

**Date:** 2026-11-16
**Status:** accepted (the author's standing rule of the scenario test of 2026-11-15: a blocker is fixed on the fly; finding E2-01); amends ADR-012 erratum 2 and SPEC 10 ("umask 077") for the project directories, and ADR-049 (erratum 8)

**Context:** Every `archiwista` command, its job processes and its area reader run with `umask 077`, so that the index, the state database (accounts, password hashes, sessions), the job logs, the area copies and the launch file are the account's alone, whatever the computer's umask (SPEC 10, "Private local data"). The same umask also applied to what Archiwista writes on a person's command in a project's directory, outside its local data: `archiwista-project.json`, `obszary/*.geojson` and `eksport/` were `0600` files in `0700` directories, whatever the service's `UMask` and the folder's permissions. A project is written to be read by other tools, without Archiwista (ADR-049 decision 1): in a team deployment Hydrograf's bootstrap reads it as another account of the folder's group, and refused it (`project_file_unreadable`, exit 9), unless someone ran `chmod -R g+rX` after every change. The snapshots of own data met the same problem and give the new directories of `.wersje/` the permissions of the data folder (plan v0.2, decision 9).

**Options:**
- A) A setting, e.g. `[projects] group_readable = true`, giving `0640`/`0750`. Rejected: another key to learn for a rule the folder already states, and a fixed group mode that ignores a folder meant to be private (or open to all).
- B) Honour the umask the process started with for the project directories. Rejected: the job and reader processes set `077` in their own `main` and would need the value passed down; a desktop's umask `022` would make the files readable by every account even inside a private folder, and the folder's owner could not choose without restarting the service.
- C) Always `0640`/`0750`. Rejected: like A, it ignores the folder.
- D) Each entry Archiwista writes in a project's directory takes the permissions of the folder it is written in, as the snapshots do.

**Decision:** D.

1. **The rule.** A file Archiwista writes in a project's directory gets the read and write bits of its folder (`folder_mode & 0o666`: `0640` in a `0750` folder, `0600` in a `0700` one, `0660` in a `2770` one); a directory it makes gets all nine bits of its parent, its other bits kept (a set-group-ID directory makes its children set-group-ID and of its group, as the system already gives them). The umask of the process does not take part: the folder's owner decides who reads the projects with the folder's mode and group.
2. **Where.** `make_project_directories` makes a new project's missing directories below the configured project folder, each with its parent's permissions; an existing directory is the person's and is left as it is. `obszary/` and `eksport/` get the project directory's permissions whenever an area or an export is written (also one an older version left `0700`). Every project file and area file written through `_write_atomic` gets its folder's bits before `os.replace`, so each rewrite has them, and a file an older version left `0600` gets them at its next change. An export's directories and files get them before the export is swapped in, and its ZIP before it is moved into place. The lock `.archiwista-project.lock` is not given them: it is Archiwista's alone and lives only while a change runs.
3. **A file system that refuses.** A `chmod` refused (`EPERM`, `EACCES`, `EINVAL`, `ENOTSUP`: a CIFS mount with its own modes, ACLs, an entry of another account) is no error; the entry keeps the mode the file system gave, logged at the level `debug`. On Windows nothing changes.
4. **What stays.** The local data (the data directory `0700`, the index, the state database, the job logs, the area copies, the preview cache, the work directories, the launch file), the state export and the action log export (`0600`), the TLS key and the settings file keep the `umask 077` and their modes; nothing of them lies in a project's directory.

**Consequences:** A project folder `2750` of a group the bootstrap's account belongs to (a systemd unit's `UMask` no longer matters for it) gives `0640` files and `2750` directories, and Hydrograf reads every project, area and export Archiwista writes without a `chmod`. A desktop project folder made under umask `022` (`0755`) now holds `0644` files where it held `0600` ones: other accounts of the computer that may enter the folder read the projects; a person who wants them private keeps the folder `0700`, which gives `0600` files as before. Files a version before this one wrote keep their mode until they are written again (`chmod -R g+rX <project folder>` once fixes them). `archiwista doctor` does not check project folders.
