(`v02-own-smb-run1.log`) stopped at the row change before the second
snapshot: a `sqlite3` write to `plan.gpkg` on the share ends with
`database is locked` even without any other process (checked
separately: `BEGIN IMMEDIATE` succeeds, `COMMIT` after 2 s — `SQLITE_BUSY`).

does not escalate to an exclusive one. The first snapshot (in-place read,

`?nolock=1` (nobody else touches the file in the meantime); run 2 —
results in the table. Conclusion for the user: a GeoPackage editor working
from Linux through such a mount will not save the file; Archiwista (read-only
without locks or through a copy) is not affected.

## 6. Performance error found and the fix

**Layer thumbnail of 35 ASC sheets: 2.61 s p95 (target 2 s).** In-process profile
(`compose.layer_thumbnail`, 2.9 s): shading computed for
the whole layer frame for every version — 1.57 s (35 × 512 px frame, of
which a sheet covers about 1/35), PNG encoding of 35 frame thumbnails 0.66 s,
`_rgba` 0.2 s, warp 0.3 s. Fix (`archiwista/previews/renderers/raster.py`,
`_paint_within`): the thumbnail in the frame is painted with the style only in the grid window
with values (with the style margin) and placed into a transparent frame — the same
pixels (checked on 1800 random grids for each style:
byte-for-byte equal; `test_raster_renderer`, `test_raster_styles`,
`test_compose`, `test_raster_cog` — 37 green, `test_local_layers` —
13 green). In-process 2.9 → 1.3 s; over HTTP p95 2610 → 1306 ms
(35 ASC), 1435 → 1234 ms (50 SM5). Thresholds were not lowered.

## 7. Limitations and open items

- **GPU** (criterion 5) — section 4. **SMB** — all targets in the SMB column
  and the v0.1 regression are met (section 5); borderline: map of 4964 footprints
  295 ms (local index, under load).
- **`/local-layers` at the edge of the target** (902–1052 ms against 1 s) for an area
  with 56 layers and 779 versions; once previews are built, the response computes
  the state, addresses and `v` for each layer — measuring the components before
  the release is recommended, in case a run on a clean machine exceeds 1 s.
- **The SM5,125 Mpx sheet from decision 12** corresponds to 20 cm; current
  ČÚZK sheets (12.5 cm) have 320 Mpx. The real sheet was built in 6.9 s —
  faster than 125 Mpx (7.3 s), because GDAL reads JPEG with a DCT scale of 1/4 instead of
  1/2. Proposed change to the row description in SPEC 4.5 (step 18): "SM5
  JPEG sheet (125–320 Mpx)".
- The snapshot measurement GeoPackage is 123 MB instead of 100 MB (460,000 polygons
  as in step 8) — a conservative measurement.
- Measurements ran in parallel with the work of other contributors; p95 of the map of 4964 footprints under
  load is 285.6 ms (target 300 ms).
