**Date:** 2026-10-18. **Code:** Archiwista `develop` after `9d9da71` with the fixes
of this step (section 6), Kartograf 0.8.0 from the branch `feat/archiwista-store-api`

  (4 CPUs), 15.6 GiB RAM, Debian 13.5, Linux 6.12.94; SSD GOODRAM SATA
  `/dev/sdb` (`rotational=0`), ext4 `rw,relatime`. Python 3.13.5, SQLite

  (`enp3s0`, 1000 Mb/s).
- **Store:** `python -m tests.fixtures.make_store --slots 50000 --seed 1
  --projects 30 <data-dir>/store-50k` — 51,050 slots (50,006 links
  of the standard path and 1,044 `full_sheet/`), 80,056 versions, 262,244 files
  (102,154 with more than one hard link), 201,290 directories,
  30 projects, 2.3 GB, 17 segments (with edge cases). Copied to the share
  preserving hard links (`<share>/store-50k`, 813 s).
  **Generator time:** 109 s (writing and verification with Kartograf's readers);
  `test_store_50k_generator_reproduces_store` rebuilt from the seed a store
  identical to the measured one (paths, sizes, link counts).
- **Method** (`tests/perf/test_store_50k.py`): a real `archiwista serve`
  as a separate process (configuration and index local in
  `<data-dir>/perf-50k-<ssd|smb>/`, offline mode, scheduler interval
  1440 min so that a scheduled scan does not fall into the measurement), a session like the agent's
  (one-time token). The full scan is the first scheduler scan after startup,
  the incremental one is `POST /stores/perf/scan`; time = `finished_at − started_at`
  of the job (including starting the worker process). Queries over HTTP (httpx,
  keep-alive): 40 samples after warm-up, p95 = 38th of the sorted ones. Memory:
  `/proc/<pid>/status` of the server and its worker processes every 50 ms, and
  `smaps`. Measurement without code coverage (`--no-cov`). The filesystem
  cache was not dropped (no root permissions).

## 6. Errors found and fixes

1. **40 ms delay on every browser request** (`archiwista/server.py`).
   The server socket was created as `socket(AF_INET, SOCK_STREAM)`
   with protocol 0, and asyncio disables the Nagle algorithm only on connections
   of an `IPPROTO_TCP` socket. A response sent in parts waited for the client's delayed
   acknowledgement: on a keep-alive connection every request took
   about 44 ms (a static file and `/api/v1/session` too). Fix: a socket
   with `IPPROTO_TCP`; file card 52 → 3 ms, `/health` 72 → 10 ms. Regression
   test: `tests/integration/test_serve.py::test_serve_connections_send_without_nagle_delay`
   (red before the fix).
2. **Server memory 638 MiB RSS** (`archiwista/index/schema.py`). Each
   index reader (one per server thread) memory-mapped up to
   256 MiB of the index, so the same pages were counted in RSS multiple times.
   Fix: readers without `mmap` (pages from the file system
   cache); the writer unchanged. Server RSS peak 179 MiB. Cost:
   queries that walk whole tables in the process are 30–60 ms slower —
   within thresholds thanks to fix 1.
3. **"przypięte" (pinned) list p95,228 ms** (`archiwista/index/queries.py`). The filter
   checked `EXISTS` for each of the 80,000 versions; it now selects versions
   from the pins (`IN`): median 6.6 ms, the same rows and group counts.
4. `docs/SCOPE.md`: v0.5 dependencies supplemented with IMGW-20 (dataset
   key convention, "v0.5" in SPEC 12.7).

## 9. Run 3 — segment parts and known version directories (2026-10-19)

**Code:** Archiwista `develop` `d5cf48f` (with `fc144bb`–`78038da`: the
`full_scan_interval_h` setting and the time of the last full scan), Kartograf 0.8.0
from the `feat/archiwista-store-api` branch (`4c0ea08c`, `55cac64f`:
`list_partitions`, `iter_store(partition=…)`, mapping in `skip_versions`,
ADR-045 erratum 1). Computer, store and share as in section 1; the same

scan, view refresh, list and search, sidecars, memory).

Changes (erratum 1 to decision 3 of the plan, SPEC 4.4 and 12.1):

1. **Segment parts on the share.** A segment is read in `list_partitions`
   parts (e.g. `nmt/pl_1992` — 75 parts, `orto/cz_sjtsk` —
   715), the `scan_threads` = 8 pool takes the heaviest parts first (weight:
   known versions of the part); writing is still done in one thread, the progress event
   and the segment time (the sum of the parts, so in the table below the segment times on the
   share add up to more than the scan time) come after the last part. A local
   disk still uses one thread and whole segments: threads hurt there (Kartograf measurement,
   whole store by parts: 1 thread 6.1 s, 8 threads 11.8 s).
2. **Known version directories are not listed.** The index provides a mapping
   version directory → file names only for directories whose files were all
   valid versions at the last read; directories
   with a problem or with a "brak pliku" (file missing) version are read as new. A file removed
   or added inside a known directory is seen by the full control scan
   (`full_scan_interval_h`, default 24 h; "Pełny skan" (Full scan) in "Magazyn" (Store);
   time in "Magazyn", `/health` `full_scan_at`, `archiwista status`) —
   `tests/integration/test_scanner.py::test_file_removed_inside_known_version_dir_found_by_full_scan`.
3. **View refresh** also takes the known slot directories from the same
   directory (`IndexWriter.slots_beside`). Profile before the change (SMB,
   492 units): 6535 `scandir` calls, of which 4850 were listings of version directories in
   `versions/bbox/` — the version directory name does not contain the unit, so
   every batch with the `bbox` unit listed all of them; this one batch
   took 11.2 s with a median refresh of 9.1 s.
